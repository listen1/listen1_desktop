# Listen 1 Windows 维护记录（2026-09-22）

本轮交付保留 AngularJS 和现有界面的修复代码、三层精确锁文件、可重复测试及 Windows x64 测试包。最初确认的五类本地故障已有回归验证。六个平台各有两首游客样本完成 30 秒直接播放、音频输出检测、暂停、定位和恢复；仍有特定曲目不可用及 QQ 请求间歇返回业务码 2001，不能描述成全部平台、全部曲目或账号流程已经修复。

## 环境与基线

- Windows 11 x64，系统 build `10.0.26200`；Intel Core Ultra 7 255HX，约 31 GiB 物理内存。实际显示缩放下截图为 1500×1005，对应 1000×670 逻辑窗口。
- 工具链 Node 24.21.0、npm 12.0.2、Playwright 1.63.0。应用 Electron 44.4.3 / Chromium 152.0.7977.130 / Node 24.21.0。
- 全部在线测试为游客，使用独立 `dist/maintenance/<run>/profile`。应用使用系统代理；QQ 诊断另比较 direct 和 system，均出现成功响应。没有读取用户真实 Cookie、备份或音乐，没有登录、购买或发布操作。
- 根仓库基线 `cccd1b8829b523a57fc237de6f459011d0b0b2cb`；子模块基线 `c1bfbc2a60a03de1c6e37474f6ce6ca6322afd02`。子模块指针未变，两个仓库保留未提交修改。
- 原有用户修改是 `app/main.js`、`app/floatingWindow.html` 及两份未跟踪的 AGENTS.md。首次快照记录中的 scripts/tests 是准备快照时加入的测试工具，不是用户原有业务改动。原始源码快照保留在 `dist/maintenance/baseline`。

本机验证不扩展为其他 Windows 版本、macOS、Linux、arm64 或浏览器扩展认证。汇总原始证据和包哈希见 [validation.json](validation.json)，队列原始样本见 [queue-performance.json](queue-performance.json)。

`request.js` 管理任务生命周期；provider 负责参数和数据转换；MediaService 负责路由、聚合、缓存和换源；controller 负责界面和 Angular 更新。旧 `.success(fn)` 保留，网络门面加入 `.error(fn)`、`.cancel()` 和 Promise，搜索提供进度订阅。单曲地址及搜索传递 AbortSignal；尚未改造为 signal 请求的传统歌单内部 HTTP 由 Axios 超时兜底，任务取消会阻止其回调更新 UI，并不声称所有旧 provider 的传输都能立即中断。

播放继续通过 `l1Player` / `BG_PLAYER:*`，没有把桌面 API 混入 provider 请求逻辑。播放器复用短时地址缓存，但每次回到旧曲目创建当前代次的 Howler 回调；本地标签最多并发 4 个、一次批量更新歌单。

桌面新增专用 preload 与 `listen1Desktop`；所有页面 Node/remote 调用已迁移，移除 `@electron/remote`，主窗口隔离且关闭 Node。主进程校验窗口、frame、准确本地来源、操作和参数；登录窗口开启 webSecurity/sandbox，Cookie 域和字段受限。原有歌词原文/翻译、拖动边界和 textContent 修改保留。更新检查异步且失败不阻塞播放，测试启动跳过；更新源和设置页版本源分别核对为桌面上游，未执行真实更新安装。

## 性能记录

同机五次核心入队/JSON 序列化，使用固定 1,000 首合成数据：

| 指标                |     更新前 |  更新后 |
| ------------------- | ---------: | ------: |
| 事件                |      2,000 |       2 |
| 全队列快照          |      1,000 |       1 |
| 累计快照曲目记录    |    500,500 |   1,000 |
| 序列化字符数        | 49,840,990 |  99,781 |
| 核心+序列化中位时间 |   60.50 ms | 0.60 ms |

该基准不包含 DOM、Angular digest 和磁盘。实际 Electron 中入队检测同样只有一次 1,000 项快照，单次同步操作约 0.5 ms；不能把微基准倍数直接当整应用提速倍数。

同机启动观测：原版首次 2,236 ms、另一轮 980 ms；本地修复后旧 Electron 964 ms；换 Electron 44 为 1,014 ms；全部依赖后的启动样本 901 ms。均是进程启动到页面就绪，未清理 OS 缓存、未重启机器，不是严格冷启动统计，不能据此宣称固定百分比提升。

最终源码在线搜索完成观测约 1.55～2.35 秒；从自动化点击到进度阈值约 2.2～2.62 秒，包含 Playwright 调度和请求延迟，不是精确首声测量。早期门面调用的 0.5 秒样本使用不同调用方式，不能用于比较回归。一次五平台/十首样本前后渲染进程工作集约 129→233 MiB（峰值约 243 MiB）；包含搜索结果、图片和缓存，没有相同旧运行时长基线，不能宣称无泄漏。长期连续播放、严格首声/冷启动、批量本地导入的前后耗时仍未形成可比较结论；本地并发上限和单次歌单提交已验证。
